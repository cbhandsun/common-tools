# PPT Repair Playbook

Use this file as the action library after identifying issues.

## 1. Crowded Slide

Symptoms:
- Too many objects compete
- Tiny type
- No dominant focal point

Repair moves:
- Remove decorative noise
- Promote one focal object or takeaway
- Merge repeated labels
- Shorten supporting copy
- Increase margins and spacing between groups

If the slide still fails after cleanup, recommend splitting it.

## 2. Weak Hierarchy

Symptoms:
- Title, body, and support elements feel equal
- Audience cannot tell where to start

Repair moves:
- Strengthen title prominence
- Enlarge the main visual or takeaway
- Demote secondary notes
- Use position and scale before adding more color

## 3. Poor Whitespace and Alignment

Symptoms:
- Elements nearly touch
- Uneven gutters
- Ragged grouping

Repair moves:
- Snap related elements to a shared grid
- Normalize left edges, top edges, and card widths
- Create consistent vertical rhythm
- Leave more empty space around the most important content

## 4. Text-Heavy Slide

Symptoms:
- Paragraph wall
- Title wraps awkwardly
- Dense bullets dominate

Repair moves:
- Convert prose into headline + support bullets where safe
- Keep only the message needed on-screen
- Move detail to speaker notes or appendix if the deck mode allows
- Avoid shrinking text as the first fix

## 5. Chart or Table Confusion

Symptoms:
- Too many series
- Small labels
- Heavy gridlines
- No highlighted takeaway

Repair moves:
- Reduce chart ink
- Highlight the key series or point
- Use direct labels when possible
- Simplify legends and axis clutter
- For tables, remove non-essential columns and emphasize the comparison row/column

## 6. Accessibility Repair

Fix:
- Unique titles
- Reading order
- Contrast
- Alt text
- Meaningful links
- Legible sizing

Do not treat accessibility as separate from design quality; fix both together.

## 7. Preserve-Intent Constraints

When the user wants optimization without changing expression:
- Keep the same claims, examples, numbers, and figure-text mapping
- Avoid replacing real screenshots or diagrams unless necessary
- Avoid changing brand palette unless contrast requires it
- Prefer layout repair over narrative rewrite

## 8. Reporting Format

When closing the task, summarize with:
- What was repaired
- What was intentionally preserved
- What still needs a user decision
