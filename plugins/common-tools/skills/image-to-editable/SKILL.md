---
name: image-to-editable
description: Convert an approved image into an editable PPTX using the hosted Common Tools Runtime.
---

Use this Skill only with the installed `common-tools` HTTPS MCP server and only for a user-approved PNG, JPG, or JPEG. The heavy OCR, reconstruction, rendering, and quality work runs on the server. Do not run `common-tools editable run`, look for `slideclone.js`, install PaddleOCR, .NET, LibreOffice, or PowerPoint, or fall back to an ad-hoc local PPTX generator.

The service accepts one gzip-compressed TAR containing either `assets/source.<ext>` for a single page or contiguous, explicitly ordered `assets/source-001.<ext>` through `assets/source-020.<ext>` entries for a batch. Prefer `common-tools team raw-image-archive --input <png|jpg> --out <archive.tar.gz>` for one image or `--inputs <ordered,comma-separated,paths>` for multiple images when the matching Local Runtime is installed. Otherwise create the transport archive in a new temporary directory with the operating system's standard TAR implementation. Preserve every source extension and requested order; do not include unrelated files, follow symbolic links, overwrite an existing archive, or exceed 20 images, 20 MiB per image, 60 MiB total extracted bytes, 16,384 pixels per dimension, 40,000,000 pixels per page, or 200,000,000 pixels per batch. Delete temporary copies after the upload attempt. The server repeats all validation and rejects malformed, discontinuously numbered, oversized, or unsafe archives.

Call `create_team_upload_target` with `capability: "image-to-editable"`, `contentType: "application/gzip"`, and the archive's exact byte length. Upload only that exact archive to the returned short-lived `uploadUrl` using HTTP PUT with the prescribed headers. Never log or expose the signed URL, never reuse it, and never upload to a different address. Then call `create_team_job` with `capability: "image-to-editable"`, the returned object key, and a new opaque idempotency key. Retry with the same key only when retrying the identical submission.

Poll `get_team_job` with the returned job ID until it reaches a terminal state. On success, inspect the bounded summary and obtain only a reported artifact through `get_team_artifact_target`; download it to the user-approved workspace without exposing the signed URL. Report the quality status exactly as returned. A batch must pass `raw-image-batch-validated`; its pages are rebuilt in the declared order and visual metrics report the worst compared page. When a fidelity residual is present, require `residual-native-duplicates-removed`; this proves reconstructed native objects were removed from the raster residual so moving them will not expose duplicate pixels. A generated PPTX is not automatically high-fidelity: do not claim verified quality when this gate, `quality-rendered`, or `visual-fidelity` is unverified or failed. Use `cancel_team_job` only when the user asks to cancel.
