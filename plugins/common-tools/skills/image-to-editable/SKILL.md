---
name: image-to-editable
description: Convert approved images, a PDF, or an image-based PPTX into an editable PPTX using the hosted Common Tools Runtime.
---

MCP task status `completed` means polling ended; it does not by itself mean the conversion succeeded. Check the task result `isError`, the structured Job status, and `quality.passed`. Only a `succeeded` Job with `quality.passed: true` is a successful conversion. A required quality-gate failure may retain reported artifacts for diagnosis; download one only when useful and label it clearly as a quality-failed diagnostic output rather than a successful result.

Use this Skill only with the installed `common-tools` HTTPS MCP server and only for user-approved PNG/JPEG images, one PDF, one image-based PPTX, or source-backed structured Deck IR prepared from those approved sources. The heavy document normalization, OCR, reconstruction, rendering, and quality work runs on the server. Do not run `common-tools editable run`, look for `slideclone.js`, install PaddleOCR, .NET, LibreOffice, or PowerPoint, or fall back to an ad-hoc local PPTX generator.

The service accepts one gzip-compressed TAR containing `assets/source.<ext>` for a single PNG/JPEG, contiguous `assets/source-001.<ext>` through `assets/source-020.<ext>` entries for an ordered image batch, or exactly one `assets/source.pdf` or `assets/source.pptx`. Prefer `common-tools team editable-source-archive --input <png|jpg|pdf|pptx> --out <archive.tar.gz>` for one source or `--inputs <ordered,comma-separated,image-paths>` for multiple images when the matching Local Runtime is installed. Otherwise create the transport archive in a new temporary directory with the operating system's standard TAR implementation. Preserve every source extension and requested order; do not include unrelated files, follow symbolic links, overwrite an existing archive, or exceed 20 output pages, 60 MiB source/normalized bytes, 16,384 pixels per image dimension, 40,000,000 pixels per page, or 200,000,000 pixels per image batch. PDF/PPTX packages must be complete and a PPTX must pass bounded OOXML admission before upload. Delete temporary copies after the upload attempt. The server repeats all validation, uses fixed LibreOffice/Poppler arguments for document normalization, renders at most 21 pages to detect overflow, and rejects malformed, discontinuously numbered, oversized, or unsafe inputs.

When the approved source has already been understood as native components, preserve that work using the existing structured Deck IR path instead of rasterizing it and repeating OCR. With a matching Local Runtime and Worker that support structured source verification, use `common-tools team editable-source-archive --input <deck.json> --out <archive.tar.gz>`. The deck must contain `page.source.pageImage` for every page, pointing to its approved full-page PNG/JPEG under `assets/`; cropped icons remain separate `images[].assetPath` entries. Reuse the existing local component/connector builders and icon-crop refinement to prepare the IR; do not invent component relationships from OCR order. The command validates the deck, copies only referenced assets, and preserves editable objects. Require `deck-ir-validated`, `quality-rendered`, `visual-fidelity`, and `complex-graphic-native-gate` on the returned Job. A legacy Worker that accepts Deck IR without reporting those checks has not verified this path. This route reuses supplied component understanding; it does not imply automatic understanding of arbitrary source pages.

Call `create_team_upload_target` with `capability: "image-to-editable"`, `contentType: "application/gzip"`, and the archive's exact byte length. Upload only that exact archive to the returned short-lived `uploadUrl` using HTTP PUT with the prescribed headers. Never log or expose the signed URL, never reuse it, and never upload to a different address. Then call `create_team_job` with `capability: "image-to-editable"`, the returned object key, and a new opaque idempotency key. Retry with the same key only when retrying the identical submission.

Poll `get_team_job` with the returned job ID until it reaches a terminal state. On success, inspect the bounded summary and obtain only a reported artifact through `get_team_artifact_target`; download it to the user-approved workspace without exposing the signed URL. Report the quality status exactly as returned. An image batch must pass `raw-image-batch-validated`; a PDF/PPTX must pass `document-pages-normalized`. Pages are rebuilt in declared/source order and visual metrics report the worst compared page. Raw-image output must also pass `local-production-profile-aligned`, proving every page used the same production reconstruction profile as the local high-fidelity chain. That profile retains refined local icon crops when native icon approximation would lose detail, while keeping text, containers, connectors, tables, and banners editable. When a full-slide fidelity residual is present, require `residual-native-duplicates-removed`; it must erase both reconstructed native objects and retained local crops before those objects are overlaid, so moving them will not expose duplicate pixels. The default visual limit is `pixel-diff-ratio <= 0.08`. A generated PPTX is not automatically high-fidelity: do not claim verified quality when these gates, `quality-rendered`, or `visual-fidelity` are unverified or failed. Use `cancel_team_job` only when the user asks to cancel.
