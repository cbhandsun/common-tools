# 图片转原生可编辑 PPT：分场景识别与验证

2026-10-01 的主流程复核与新增六个项目源码对照见 [结构优先路线](image-to-editable-semantic-first-plan.md)。后续优先验证全局区域与关系表示的收益；下文已有局部修复和研究记录不代表默认 Worker 已具备这条新流程。

本次调研将 Dolphin 的分阶段解析、next-ai-draw-io 的显式关系图、AntV Infographic 的信息/布局/外观分层，以及 Design2Code、PPTAgent、Surya 的评估和几何契约方法统一到该路线。项目对照、适用边界、P0–P3 交付物和阶段验收均以链接文档为入口；两张新图仍未达标，研究结论尚未成为默认识别流程。

## 原则

识别输出是带坐标的候选证据，不是可交付 PPT 的证明。文字、容器、连线、图表和独立图示需要分别识别，再通过像素归属和实际渲染组合。最终必须同时通过原生结构、语义、视觉门禁以及编辑保存重开验证。

固定视觉门限保持 PDR ≤ 0.08、前景缺失 ≤ 0.12、MAD ≤ 12；Worker 总预算保持 540000ms。分类提示、模型置信度和对象数量不能替代这些门禁。

## 行业方法与适用边界

- [PP-StructureV3 / PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)：把文字识别、版面区域和表格等结构信息结合，保留细粒度坐标。适用于建立区域候选；文档解析结果仍需源像素和 PPT 渲染验证。本机此次测试运行的是 Umi PaddleOCR-json-v2，不是仓库文档中的新模型。
- [Docling](https://github.com/docling-project/docling)：分离版面、阅读顺序、OCR、表格和图表等任务。这里可借鉴其任务分工，避免 OCR 阅读顺序被误当作流程图连接关系。
- [MinerU2.5](https://arxiv.org/abs/2509.22186)：先以低分辨率理解全局版面，再以原分辨率识别局部内容。这里可借鉴分层定位和按需局部处理；低分辨率坐标必须可追溯地映射回源图，避免浅色边框、小字和压缩细节丢失。

这些方法不意味着应立即接入所有模型，也不证明可以矢量化任意插图。本轮没有安装模型或升级识别服务。

## 场景矩阵

| 场景 | 全局定位 | 局部证据 | 重建和拒绝边界 |
| --- | --- | --- | --- |
| 干净卡片、结构图 | 面板闭合边界、文本分组 | 四边闭合、填色、端点及完整连接拓扑 | 文本与容器原生；语义 archetype 失败后仍可尝试有完整实测证据的通用图，不能根据 OCR 次序合成边 |
| 密集架构 JPEG | 层次区域、文本密度、压缩背景 | 原分辨率文字带、边框连续性、连接端点 | 保持正文原生；噪声或文字碎片不占用图示候选存储，实际扫描仍计入固定预算 |
| 手绘、斜字、弯曲边框 | 文字与关系区域分工 | OCR 四边形、实测文字墨迹、曲线轮廓及归属 | 区分旋转与变形，避免把整张图作为一块截图；不凭颜色或标题推定结构 |
| 独立人物、图标、复杂插图 | 图示 ROI 与正文隔离 | 原图尺寸、原始/映射/紧裁坐标、保留的多部件细节 | 无可靠 primitive 证据时保留精准小裁剪；不能先删除原图示，再把原生近似拒绝后留下空洞 |
| 截图、照片与纹理 | 内容区域与 UI/正文分离 | 原图纹理、真实边界、覆盖文本检查 | 承认图像本身不能整体原生编辑；正文和可测 UI 结构单独重建，不能隐藏文字冒充可编辑 |
| 表格与统计图 | 表格/图表候选区域 | 网格边界、行列归属、坐标轴、刻度与系列 | 只有完整实测证据才能恢复单元格或数据系列；模型生成的数据需另行验证，不能凭曲线猜数值 |

## 统一的证据链

1. 固定源图身份和每次几何变换，保留原始 OCR 与局部 OCR 各自的证据文件，不能以最后一次 crop OCR 覆盖原始结果。
2. 全局版面定位独立于原生连线检测。真实面板存在时，排除误检边框不应改变正文保留策略。
3. 区域候选先验证文字、容器、连接、图示的归属。闭合背景只拥有匹配填色的像素；内部未恢复前景不属于背景。擦除依据不可变源图，避免受操作顺序影响。
4. 每个保留的小裁剪携带完整坐标与处理证据。精确裁剪没有清除邻域像素时，如实记录零清除，并保留实测多部件数量；不得伪造精修结果。
5. 原生候选与发布产物分开。搜索和 shadow checkpoint 仍遵守现有结构与非回归政策；严格拒绝原因进入有界日志。不能因为总 PDR 下降就忽略局部文字退化。
6. 先在缓存证据上重放根因，再冻结生产代码运行真实 Worker。避免每次失败从 OCR 和同一批候选重头开始。
7. 诊断观察器必须透传原本的渲染页回调。保存预览不能截断 Worker 的文字精修反馈；同时保存每次验证的 IR、PPTX 哈希和源图身份，不能把最低全局指标文件误绑定到另一候选。
8. 多部件识别窗口可以聚合，但聚合对象必须保留所有原始部件 ID。局部回退比较固定源区域，撤销退化区域及其耦合追加对象，再重新生成、渲染和检查；回退自身不授予质量通过。
9. 单个外框和多段文字不足以证明表格。单列表格也必须有至少两行的实测分隔；重复分隔缺失时，交给面板识别，不能生成整块单元格填色盖住内部图示。单元格背景只拥有与源填色匹配的像素，内部前景归属独立验证。
10. 原生图示替换使用独立候选事务。已通过基线只能被再次通过固定门禁的候选替换；构建、渲染失败及取消均清理本候选文件，并保留基线。非回归容差不能授权把合格结果替换成不合格结果。拒绝诊断区分结构、视觉退化和已通过门禁丢失，日志不包含源文案或异常原文。

## 2026-10-01 根因证据与适用限制

本轮直接读取 PP-StructureV3 官方算法说明、Docling 官方 README 和 MinerU2.5 论文摘要，核实布局/阅读顺序/表格的任务分工及全局定位后原分辨率局部识别的方法。官方方法介绍不是本项目上的性能对比。当前 Umi OCR 未替换，也未安装这些模型。

- [PP-StructureV3 官方算法说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-StructureV3/PP-StructureV3.en.md)：布局、文字、表格、图表、阅读顺序各自提供证据。表格识别必须验证重复分隔，不能把阅读顺序直接解释为图的边。
- [Docling 官方说明](https://github.com/docling-project/docling)：布局、OCR、表格和图表分别处理。关系图端点恢复仍需要专门的源像素验证。
- [MinerU2.5 论文](https://arxiv.org/abs/2509.22186)：明确采用全局低分辨率版面分析、原分辨率局部内容识别。适合减少密集文字的无效全页重试，但不负责证明 PowerPoint 编辑后没有重复残影。

手绘图缓存证据中，文字包围盒内有 169277 个去重后的浅色彩色源像素被残差擦除成透明；诊断见 `.codex-temp/text-background-ownership-110.json`。这是确认整块文字遮罩丢失背景的像素证据。探针中的亮度/色差仅用于诊断，没有进入生产归属规则。单纯重新填色仍可能保留字形或覆盖图示，因此文字墨迹分割和背景恢复尚未完成安全接入，不能把它描述成已修复。

同一图的一块面板被识别为仅一行的网格，生成 `line-text-native-grid-cell` 全面覆盖内部前景。已收紧重复网格证据并补背景归属回归：单个外框拒绝表格生成，真实重复单元格保留内层图示。回归覆盖改文案、平移、缩放和改色；旧成果继续只读。

新的识别模型如需加入，先以同一源集和同一总预算进行可重放的影子评估。手写文字、图示误识别为字、密集 JPEG 小字分别记录字行错误及坐标误差；图结构记录节点与端点附着；整页仍采用当前固定视觉与原生门禁。不能把模型自报置信度或文档解析成功当作可编辑成功。

## 为什么此前没有一步到位

问题发生在多个环节之间，而非单一 OCR 模型准确率：排除误检结构线改变了正文保留路径；背景拥有整块包围盒而遮住内部前景；精确小裁剪缺少审计字段而阻断候选；诊断脚本覆盖渲染页收集回调而跳过依赖渲染图的精修。候选还可能改善一个图示、损坏另一个图示，并丢失聚合窗口的原始归属。仅观察最终 PDR 或原生对象数无法区分这些原因。

前述修复均采用内容无关的源几何、像素和来源证据。行业方法用于确定任务分工与局部处理策略；没有把识别模型置信度直接转换成发布许可，也没有采用用户图片专用分支。

## 后续识别服务选择

### 布局解析的具体改造顺序

2026-10-01 再次读取上述三份官方资料，并补充 [SAM 2 官方说明](https://github.com/facebookresearch/sam2)。SAM 2 提供可提示分割和自动掩膜生成；其掩膜不能直接证明区域是正文、图标或某条连线，也不能证明图关系方向。此次仍未安装或接入新模型，不能引用这些模型的公开基准成绩作为本项目两张图片的验收结果。

当前更合适的结构是“区域树 + 关系图 + 像素所有权”，三者分别记录包含关系、连接关系及实际像素，而不是以一个 archetype 标签决定整页重建。

| 层次 | 可借鉴方法 | 本项目需要的约束 |
| --- | --- | --- |
| 全局区域树 | PP-StructureV3 的布局任务；Docling 的统一文档结构；MinerU2.5 的低分辨率定位 | 大区、子面板、字行、图示分别有 ID 和父区域；同页可混合多类区域；保留原图坐标和变换，不以阅读顺序生成连接 |
| 原分辨率局部证据 | MinerU2.5 的原分辨率 crop；专门 OCR、表格识别、图标轮廓 | 手绘四边形、小字和 JPEG 压缩区域按需处理；只复查不确定区域；缓存绑定源图身份、区域和识别器版本 |
| 掩膜与层序 | SAM 2 的精细分割思路；源轮廓和已测填色 | 背景、文字墨迹、容器边缘、图示和连线分别拥有像素；模型掩膜仍要过正文覆盖与源像素检查；不得按包围盒整块擦除文字背景 |
| 关系图 | 实测线段、箭头头部、端点和节点边界 | 端点附着与方向均须有证据；弯曲连接与可吸附 connector 分开记录；结构不完整只回退该关系区域 |
| 重建事务 | 局部重建、局部回退、实际渲染反馈 | 每次改动绑定区域与耦合对象；先验证布局/所有权，再调整字体；已通过成果必须再次通过全部固定门禁才能替换 |

优先实施低成本的确定性证据层修复，再用固定代表集评估新的布局服务。评估应分别计算区域漏检、字行错误、图标误作字、端点附着、背景误删、移动残影、实际编辑覆盖及总耗时；不能仅用 OCR 字准确率或总体 PDR 排序。手绘、大图、小字 JPEG、表格、照片与混合关系图需要分场景结果，避免平均分掩盖特定场景的退化。

文字背景算法必须通过抗锯齿、双色背景、旋转、相邻结构、浅色文字及压缩噪声的源像素验证。目前已接入默认擦除路径，但所有权审计仍会拒绝两新图的残留核心像素；因此这是尚未完成实图验收的工作区实现，不能据此宣称生产修复完成。失败候选不得替换已通过结果，诊断渲染也不授予发布许可。

实际应按区域选择识别方法，并允许同一页混合多个方法。干净印刷正文优先成熟 OCR 的字行坐标；手写和不规则文案可评估视觉语言识别，但保留原图四边形与原文一致性检查；表格使用专门结构识别；关系图使用真实线段、箭头端点与节点附着检测；复杂独立插图保留精准小图。模型可提出区域类型与关系假设，最终拓扑必须有源像素证据。

模型升级需固定版本，在相同来源、预算和验收门限下，对代表集比较正文保留率、文字错误、连接拓扑、原生覆盖、局部视觉退化、全页指标及耗时。先做可复现的受控对比再替换生产服务。本轮尚未部署 PaddleOCR 新模型、Docling、MinerU 或新的视觉语言模型，不能把方法借鉴描述成这些服务已经接入。

### 2026-10-01 行业源码对照与布局改造建议

本次直接读取 [Docling 布局后处理源码](https://github.com/docling-project/docling/blob/main/docling/utils/layout_postprocessor.py)、[PP-StructureV3 算法说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-StructureV3/PP-StructureV3.en.md) 和 [MinerU2.5 摘要](https://arxiv.org/abs/2509.22186)，三项 HTTP 200。保存的原始资料位于 `.codex-temp/layout-research-142/`。这些可变分支上的实现只作为此次方法研究，不是已锁定的运行时依赖。

Docling 实现先处理普通内容和特殊区域，再解决同类及跨类型重叠；图片、表格和容器分别管理。对子区域存在多个包含候选时，选择更小的父容器，并用置信度和 ID 确定稳定次序。这说明区域归属应作为独立、确定性的步骤，而不能由对象生成顺序隐式决定。本项目不照搬其文档阈值，也不把区域包含率当作像素擦除授权。

建议把区域解析输出收敛到四份互相引用、各自可验证的数据：

| 数据 | 保存什么 | 不授予什么 |
| --- | --- | --- |
| 区域树 | 区域 ID、父 ID、源四边形、候选类型、识别器版本、源图身份及坐标变换 | 父容器不自动拥有子文字或子图示的像素 |
| 阅读顺序 | 同一区域内的字行次序和段落归属 | 不据此生成节点之间的连接 |
| 关系图 | 节点 ID、源轮廓、线段轨迹、箭头头部、端点附着及方向证据 | 类别标签或 OCR 置信度不补全缺失边 |
| 像素所有权 | 原生对象拥有的实际墨迹、背景见证、冲突和未解决像素 | 包围盒重合、对象数量或自报成功不能代替可编辑性 |

分场景接入顺序：印刷正文和密集 JPEG 优先验证 PP-StructureV3 的区域检测是否改善字行归属；手绘和混合版面优先借鉴 MinerU2.5 的全局定位、原分辨率局部复查；表格走独立网格和行列识别；流程图走节点与连接检测；复杂插图使用精确小图及独立语义范围。视觉语言模型可提出区域类型及关系假设；SAM 类分割可提出掩膜。二者都必须经过源几何复核，不能直接成为原生对象或擦除规则。

当前具体故障说明了这个边界：缓存实图里一个回路箭头和一个彩色关系节点被 OCR 当作字，二者置信度约为 0.637、0.489。它们没有满足现有“大于典型字高”的图示触发条件。此前仅怀疑高置信度绕过筛选不足以解释这两处错误；还需要检查小尺寸图示的线段延伸和节点闭合轮廓。不能简单扩大低置信度阈值，也不能把任何单字或圆形都删成图示。

本次已落地的确定性修复：已知字行四边形排除相邻文字作为背景见证；重叠文字计划按核心墨迹、背景见证距离及稳定证据次序确定唯一像素所有者；文字抗锯齿的归属优先于相近面板填色；截断连通域只进行一次局部复查，源文字支持范围之外的连线继续拒绝。局部复查仍受单 ROI 262144、页扫描 40000000 的原有上限约束，初次和复查面积均计入页扫描。没有加大 Worker 总预算。

后续识别调度应优先消除类型冲突和过期几何，再投入字体与间距拟合。每个任务记录所用证据版本、花费、拒绝原因和候选产物身份。发生区域类型冲突时只复查相关区域；不要重跑整页 OCR，也不要在同一错误拓扑上继续搜索字体。独立的最终验证仍需检查移动文字后是否露出旧字形、移动容器后是否留下旧边框及连接是否仍有真实端点关系。

| [EdgeFlow](https://arxiv.org/abs/2605.27332) | 将确定性 Canny 边缘图作为原图之外的结构证据，帮助 VLM 分辨连接、转折与箭头 | 作者报告工业集改善，但另一个合成集没有显著改善；边缘图会同时包含文字和压缩噪声，不能直接当作连接掩膜 |
| [SketchAgent / Sketch2Diagram](https://arxiv.org/abs/2508.01237) | 把手绘识别、符号结构和迭代验证分开；借鉴覆盖多类图的评估方法 | 结构化重绘可能改变源图布局和笔迹，不能代替源图保真。本文仅研究方法与评估，不启动代理或引入该系统 |
| [Microsoft Table Transformer](https://github.com/microsoft/table-transformer) | 区分表格检测与表格结构恢复，单独处理行列和单元格 | 表格专用模型不能把任意外框当成网格；重复分隔和文字归属仍要实测 |

针对本项目，优先顺序是：**先消除对象类型冲突，再恢复连接与包含关系，最后拟合字体和外观**。具体流程应允许区域保留 `text / connector / node / graphic / unresolved` 多个假设，而非 OCR 返回字符后就不可逆地认定为正文。

- 密集架构 JPEG：全局布局提供父区域，原分辨率局部 OCR 保留小字；独立线段/箭头检测给出结构反证。字行与线段冲突只触发局部复查，不能仅因连接到边框而删除正文。
- 手绘关系图：区域树和 OCR 四边形保留源布局；节点闭合轮廓、实测连接轨迹与端点附着单独验证。模型负责提出关系假设，规则检查源图是否支持它。
- 单字、圆形和小图标混淆：不能只用“大于典型字高”触发复查，也不能把所有小尺寸对象都改成截图。需要完整轮廓、邻域文字支持和连接证据；证据不足保持未解决并拒绝发布。
- 混合页面：按区域选识别路径；父区域、阅读顺序、图的边和像素拥有者分别保存。用局部渲染差异检查每次变更；单独通过的区域不能为整页授予通过。

新模型的受控对比应固定版本、输入、现有总预算及门限。先比较字行错误、区域归属、箭头方向、端点附着和局部缺失，再比较整页 PDR/Missing/MAD 与真实编辑行为。可以只让模型复查未解决区域，但缓存必须绑定源图、几何、识别器和证据版本；不能复用过期坐标。

### 失败识别也必须计入预算

代码核查发现 `uncertainOversizedGlyphs` 以前仅在 `sourceGraphicEvidence` 返回正面证据时扣除扫描量。负面结果已读取源像素却不扣额度，复杂页面会重复消耗时间。新增 `inspectSourceGraphicEvidence` 将判定结果与扫描量分开返回：未开始扫描为零，扫描后的空结果仍扣原额度；非法输入、单 ROI 上限和页级 4,000,000 上限保持不变。没有提高 540000ms Worker 总预算。

通用回归使用相同大小的闭合字形反例：原先 400 个候选全部执行拓扑扫描，修复后只执行原预算覆盖的 244 个，其他候选保持文字候选；成功与失败扫描均记账。不符合标点/框图检测入口的对象也不再虚扣后续扫描量。该修复证明预算核算正确，不证明那两个被 OCR 误读的图形已解决。

### 确定性的区域归属

对照 Docling 方法时，在现有 `dla-layout-adapter` 中复现了输入顺序依赖：遍历到第一个包含文字中心的区域就停止，页面大区会抢走本应归属子面板或正文区的字行。现已改为优先选择完整包含文字的最小区域；不能完整包含时比较实测覆盖，几何相同时用置信度与稳定区域 ID 决定。原有中心/重叠准入条件没有放宽。大数面积比较避免溢出，非法端点拒绝；回归覆盖嵌套、顺序反转、改文案、缩放、平移、局部重叠、空输入和极端数值。

这项修复作用于调用方提供 DLA 区域时的现有声明式重建路径，不代表默认 OCR Worker 已接入新布局模型。它决定逻辑归属，不授予背景或图形擦除权限。两张新图的箭头/节点误读和邻近图示污染仍须独立修复、重新验收。

## 回归和验收

每个根因需要覆盖改文案、改色、平移、缩放、旋转或压缩扰动中与该根因相关的变化，并覆盖空、非法、极端、安全与失败路径。新测试必须进入统一 CI。图示与正文相连、开放面板、缺失端点和证据漂移都应拒绝。

动态本体旧例已经通过的源图和 PPT 保持只读，不得被新产物覆盖。新旧样例采用相同固定门限；每轮同时比较全页指标、正文保留、前景归属、精准图示、大栅格面积、原生结构和实际编辑行为。

真实编辑验收在输出副本上执行：分别修改文字、容器、连线与小图示，保存重开确认修改存续；恢复后再次渲染，检查移动原生对象是否露出重复残留像素。编辑抽样通过不能代替整页视觉门禁。

本机 Worker、托管 Docker/API 和插件调用是不同验收范围。任一范围尚未执行时，报告中明确标为未验证。
