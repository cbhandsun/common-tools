# 组件原生化：结构化输入复用与验收

## 根因与本轮修复

此前本地成功路径先提供节点、关系、组件边界和文字坐标，再调用已有原生构建器。常用远程打包入口只能传图片、PDF 或 PPTX，导致已经理解的结构被丢弃，再次进入 OCR 和图形推断。服务端本来支持 `deck.json + assets/`，但该路径未调用源图渲染比较。

本轮复用现有 Deck IR、OpenXML 构建器、图标裁剪精修和质量比较器：

- `editable-source-archive --input <deck.json>` 保留文字、图形、连接线、表格和图表结构，只复制明确引用的图片资产，重命名为安全的 TAR 路径。
- 结构化打包必须为每页提供 `page.source.pageImage`。源图仅用于比较，不能作为整页图片加入 `images` 来冒充原生化。
- Worker 在输入接纳模块中解析源图，要求全页覆盖、PNG/JPEG、20 页、单图 20 MiB/40M 像素、总计 200M 像素，拒绝越界及软链接。
- 完整结构化源图触发现有渲染比较，缺少比较器或必需检查时质量失败；旧版无源图 IR 保持兼容，但不声称视觉验证。
- 部分源图、空输入、非法路径、超限、缺失文件、格式错误和比较失败均有回归测试。没有降低已有质量阈值。

## 验证与范围

相关回归测试 78 项通过；源图边界和打包测试最终复测 4 项通过。Lint、类型、架构预算、工作区依赖边界、插件一致性和 Runtime 打包检查通过。真实 CLI 的结构化打包也已通过。新测试由统一测试发现入口纳入，未新增跳过或提高预算。

这次完成的是已有结构理解到团队 Worker 的复用链路，以及一页实际组件原生化验证。样本用于调试，不能当作独立验收集。尚未重跑完整 16 页，也没有证明任意页面可自动识别；部署端和已安装插件未在本轮更新。后续应把其他页面的源图结构通过同一入口验证，保持源图、原生对象和局部图标的对应关系，禁止用删除大图或绕过视觉门禁替代重建。
