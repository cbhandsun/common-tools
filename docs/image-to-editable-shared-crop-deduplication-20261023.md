## 原因与修复范围

`source-crop-connector-erasure.js` 原来只读取单条可见间隙的私有绘制证明，遗漏了已生成完整原生共享线网的证明。上层替换流程已经消费共享证明，但局部底图的部分透明化没有消费，因此其中的原线仍会保留。

本次仅修改这一个生产模块，让它同时读取既有 `measuredSharedSceneRoutePaintGroups()`。必须同时满足完整、未改变的真实共享输出、私有源证明、真实 crop 注册窗口、原非透明 texel 与源 RGB 精确相等，才将该 texel 的 alpha 设为 0。公开 box、复制成员或伪造 token 不能授权擦除。源图与原资产保持，写新的 derivative；预算耗尽不发布部分结果。

两模式的擦除账本均为 1045 个像素，包含既有实现已经擦除的 339 个。与当前基线相比，**新增净擦除是 706 个像素，只改变三张图片**：underlay-4 为 629、underlay-6 为 22、underlay-7 为 55；其他 27 张图片、全部形状、文字及完整区域/语义报告保持。不能把 1045 作为新增收益，也不能称四张图片都发生了新增变化。

实际阶段工作量为 3,010,754 / 3,427,906，均在原 4,000,000 内。crop 阶段的最大计数为 3,003,049 / 3,420,201，之后既有 dash retirement 还消耗 7705；不能把 crop 末尾误称为整个阶段终值。

## 已验证边界与剩余问题

独立检查对 27 张具可信源映射的图像逐层扫描，候选局部图片中已无该 5282-cell 私有共享组件的非透明 exact-source RGB；整页 residual 仍保留 1254 / 1753 个。三张 `native-graphic-underlay-0-split-*` 没有可信映射，明确保持未知。完整去重不能由本次 706 个净擦除推断。

本次接纳依据是严格限定的源权限、可复现的局部移动收益和仍在原视觉容差内的明确代价；没有提高 PDR/Missing/MAD 阈值，没有新增“零新增失败点”门槛，也没有降低源证明要求。后续应继续解决完整 residual、原生覆盖偏差、n4/n6/n8 外框和整卡分组，不继续枚举本补丁的擦除阈值。
