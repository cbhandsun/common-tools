## 1. 结论与实施决策

当前优先工作是补齐“识别任务 → 复核 → 编译 → 完整组件选择 → 最终清单”的契约。已有原生构造、源像素测量、图标抠图、连接端口和 Office 写入能力可以继续复用。

代码与证据确认了四类问题：

1. **被拒绝的程序恢复只覆盖部分输入。** 保留模板、原 ID 关系和合法核心的坏路径修复已贯通；当前图的 tuple 错误缺少原始提案，尚不能判定是否属于已支持分支。新旧 ID 映射和旧 plan 缺失模板仍不覆盖。不得将这条已验证路径扩大解释为通用任务系统已完成。
2. **连接的表达与清单没有覆盖共享主干。** 当前路径证明针对无分叉单路径；物理图形唯一归属机制也不允许把同一主干重复作为多条关系的独立成员。
3. **表面选择不等于完整组件选择。** 已有选择器处理容器表面，节点、标签、关系及共享路径仍分开完成。仅打开开关没有带来完整成员增量。
4. **物理连接计数与逻辑关系计数混用。** 识别提示要求每条可见物理连接数一次，完成器和清单却直接与逻辑关系条数比较。当前单路径契约隐含一对一；引入共享主干后必须明确观察单位和映射，不能直接沿用等式。

同时存在三处区域边框失败和原生参数图形的测量适配问题。先闭合任务与共享图契约，再修这些测量分支，最后处理结构残留。继续重复字体、位置或颜色微调，不能解决这些依赖问题。

本方案沿用已授权的隔离生产 Worker 工程链。不更换默认模型，不调整共享服务、路由、认证，不部署，不提高门槛或扫描预算，不增加现有模型总额度；已授权分批额度以实际作业配置为准。图标可保留经过源证据验证的独立精细抠图，文字、容器和连接必须原生。

## 3. 目标架构与强制不变量

处理顺序：

```text
源图 + 源哈希
  → 安全解析与接纳：有效单元 + 待修复任务 + 历史失败
  → 有界复核：恢复明确依赖，更新任务状态
  → 源测量：表面 / 标签 / 独立图标 / 共享连接图
  → 完整组件候选：当前运行内的完整依赖与物理成员凭据
  → 共同选择与事务提交
  → 残留清理、后处理
  → 最终 IR / OOXML 成员重核验
  → 完整 Worker 质量门禁 → Office 编辑保存重开
```

必须保持的约束：

- 待修复任务、模型置信度、序列化成功标志不授予绘制、擦除、端口或完成权限。
- 物理图形只能有一个归属；多条逻辑关系可以显式引用同一共享图中的物理边。
- 任一必需依赖缺失、重复、被后处理删除或证据失效，完整组件不得通过。
- 原始失败历史保留。解除当前阻塞必须由明确的修复映射、重新接纳和最终成员证据支持。
- 未知 census 保持未知；不得当作 0。独立 census 是遗漏检测证据，也不能单独证明识别已经穷尽整图。可见连接观察单位、共享图物理边和逻辑关系分别计数，通过显式映射核验，不能机械要求三者相等。
- 原生选择和残留擦除采用同一份依赖结果；局部原生成功不能触发整区域擦除。
- 主入口只编排 stage。非平凡逻辑放在可单测模块中，不继续扩大 Worker 巨型文件。

### 批次 B：先建立共享连接图契约与清单兼容

先解决数据结构和最终审计，再写识别算法，避免后面出现“识别成功但清单拒绝”的重复施工。

先确定观察口径：旧 `visibleRelations` 的自然语言“物理连接”没有定义分叉组件、分支或端点关系的对应方式。新契约必须明确可见连接观察单位、物理边、逻辑端点关系及映射；旧清单继续适用于原单路径含义，不能把旧计数直接重解释为新图的边数或逻辑关系数。共享图场景若缺少所需独立观察，保持未验证，在原授权复核内补齐；不得用编译器自产计数冒充独立观察。

建议在现有路径程序旁增加有界 `SharedRouteGraph`：图 ID、源哈希、owner、节点/分叉点、物理边、端口、箭头端、逻辑关系到有向边序列的引用。名称为设计建议，尚未实现。

契约规则：

- 每条逻辑关系依然占用原 relation slot；图不能提供额外关系额度。
- 每条物理边只生成一次；主干不因关系数增加而重复绘制。每个箭头头部绑定明确的终端与方向。
- 共享引用只能指向同一个经过源测量的图，不能让无关关系借用任意 shape 来充数。
- 每条关系只有在完整有向路径、端口、所有物理成员都存活时才算物化。任一共享主干缺失，所有依赖它的关系都失败。
- 图的内部节点、边和派生几何工作沿用现有上限；开始实现前固定容量并补极端测试，不通过增加扫描预算解决。
- 清单采用明确的新版本或兼容扩展，同时升级 producer、codec、artifact、consumer、final audit；保留旧版本解析。不得直接取消现有唯一成员约束。
- `completeRegionPrograms`、独立 inventory audit 与覆盖 summary 必须消费同一套版本化映射。旧的 `observed.relations === program.relations.length` 不能直接用于共享图；新路径按完整覆盖与逻辑路径存活验证，旧路径的严格比较仍保留。

复用/调整：`source-scene-path-program.js`、`source-scene-observed-inventory.js`、`source-scene-inventory-materialization.js`、`source-scene-inventory-codec.js`、`source-scene-inventory-artifact.js` 及其回归。

**退出条件：** 通用 T/Y 分叉 fixture 中，两条关系共享一段主干，主干只画一次、各关系引用完整；重复占有、伪造引用、缺边、错向、跨源/跨 owner 均拒绝。旧无分叉路径行为不变。

### 批次 C：观察、编译共享图并接入 Office 连接

1. 从现有缓存与同一源扫描账本观察整个连通组件，先测真实分叉点和头部，再提取主干、支路；不能逐条关系裁断其他支路来满足单路径证明。
2. 把逻辑端点关系与可见线段分别表示。保留源图真实空隙，复用 `visible-gap-logical`、现有直线/对角 gap 与 bent-gap 程序；折线路径需要完整顶点证据。
3. 继续保留单路径校验器。图观察结果只有在分叉结构完整、未跨入邻近图形、方向无歧义时才能提交；交叉但不相连、闭环和无法证明的分叉不得猜测为成功。

### 12.3 共享图实现中的三个前置约束

1. **拓扑压缩不增加预算。** 原单路径最多 512 个 skeleton 像素点，不能把它机械作为新图的语义节点数，也不能直接提高该上限。应在原窗口与工作账本内将已证明的二度连续链压缩成边，保留分叉、端点、头部和绘制所需转折证据；压缩不能抹掉支路或缺口。首版仍只接受可证明的无环共享图，闭环明确失败。
2. **物理拥有与逻辑引用分开。** 整个新图至多使用已有 32 个原生部件；连接段、控制节点和独立头部全部计费，每条逻辑路径继续至多 16 顶点。现有对象、关系与 local/global 槽位继续原样记账；不能拆图规避上限。旧 `visibleRelations=11` 保留原义，新的独立观察必须显式说明单位及映射，不能由编译器自产计数替代。
3. **证明绑定当前运行。** 图提案、源测量凭据、逻辑路径和最终 OOXML ID 分层验证。源、配置或 compilation session 改变就失效；序列化成功标记、shape 数或端点可达性不能生成未被观察的关系。真实曲线、渐变和空隙仍须经过源测量与最终视觉验证，合成直线 Office 原型不能替代。
