据此可作的工程判断是：对需要后续编辑的流程图和架构图，先恢复正确结构及真实对象，再优化外观，是合理且有成熟工具依据的取舍。所查资料不足以宣称存在统一行业验收标准，也不足以比较本项目与竞品的成功率、速度或高保真水平。

本轮再次直接打开并核对上述四家官方页面：Microsoft 明确允许重新路由时更换同一节点上的连接点；Miro 的图片数字化说明明确要求检查结果并按需调整或重新对齐；Lucidchart 明确支持从 JPEG/PNG 重建可编辑形状；yFiles 将节点位置、路由样式、端口和总线作为可分别约束的内容。前两类证据分别证明编辑行为与重建工作流，不能互相替代，也没有证明任意截图都能一次识别正确。

## 对默认验收的调整建议

默认目标采用“语义重建”，单独保留“高保真复刻”的结果。语义重建必须检查关系清单与完整连接器、业务内容、编辑保持及视觉可读性；高保真继续按原像素门槛及源证据严格检查。两者应分别给出通过、失败或未验证，不用一个总分掩盖具体失败，也不把改名作为历史结果通过的依据。

此前“严格完整区域 9/12”只有在能指出具体缺失内容时才可解释为语义缺陷；若不足仅是装饰外框的逐像素证据或拟合差异，应记录在高保真维度。仍须逐区域核查内容与关系，不能直接把 9/12 改成 12/12。颜色、线型、端口或分支形态一旦承载业务含义，继续作为语义硬要求。

这是针对本项目目标的工程建议，不是四家工具公开发布的共同验收规范。落实时须新增可独立验证的输出策略并接入正常流水线；类型、回归、构建、安全和原有证据绑定不因产品目标调整而放宽。

## 本任务采用的目标

| 维度 | 必须满足 | 可以单独记录的差异 |
| --- | --- | --- |
| 语义 | 节点及文字不丢失；起终点、方向、标签、关键分支、回路和分组正确；不因交叉或共享描边引入错误关系 | 纯装饰变化；若颜色、虚实线或相对位置承载类别、状态、顺序等含义，则不属于纯装饰 |
| 原生编辑 | 每条业务关系使用完整原生连接器，双端正确绑定；业务文字、节点可编辑；实际移动、缩放及保存关闭重开后关系保持 | 支持范围内的走线可重新排布；不把若干独立线段或截图覆盖当成完整连接器 |
| 视觉可用 | 文字与箭头清晰，端点无歧义，无遮挡关键内容、无误导的旧线或移动残影；核查交叉与分叉的可辨性 | 不改变含义的圆角半径、渐变、轻微折点、阴影及背景纹理差异 |
| 高保真 | 原 PDR ≤ 8%、Missing ≤ 12%、MAD ≤ 12 及原严格结果继续独立输出 | 高保真与语义可用分别给结论；不能改写原失败或用全页平均值代替小字、箭头与残影检查 |
| 工程发布 | 类型、Lint、回归、构建、安全、安装消费及适用生产流程验证 | 不因视觉目标调整而跳过失败；产物通过也不等于共享 Worker 已部署 |

本任务的“每条关系一条完整原生连接器”是用户明确要求及项目输出契约，不将其冒称所有工具的统一内部表示规范。共享网络仍须保留关系清单与必要物理绘制依据，不能为合并对象而丢掉分支或循环。

产品目标在本次用户选择后已经明确。2026-10-27 已新增显式 `outputPolicy: 'semantic-native'`，接入 Core 正常构建入口及服务端工厂的可信依赖选项；默认 `source-fidelity` 及现有严格门禁保留，任务 metadata 不能安装或切换策略。该功能未部署到共享 Worker，也未宣告整页交付成功。

新策略在最终私有封存之前选择图片层：要求完整区域清单、实际成员与既有获准替换事务核验通过，仅省略明确标为已擦除且无成员、端口或分组引用的非受保护重建残余；保留来源不明图片、受保护最小图标和全部原生形状及文字。选择前的严格语义失败独立保存；选择后的语义检查必须实际通过，随后仍执行原有源清单、文字恢复及原生组件封存与审计。没有重新计算或扩大已批准的背景像素范围。

## 通用的一次生成路径

在源关系已确认且目标连接器可表达的支持范围内，链路应直接执行：解析节点及关系 → 校验关系图、方向和必要端口 → 共享网络整体路由 → 每条逻辑关系生成完整原生连接器 → 核验绑定与关键拓扑 → 渲染及编辑验证。

圆角或渐变拟合失败应进入有记录的外观降级，不应让关系退回碎线。源关系有歧义、图型不受支持或连接器无法表达时，报告具体未满足项，不能猜测关系或用原图底层伪装成功。常规支持图型可以一次生成；任意复杂截图的一次正确识别尚无本次实测证明。

避免继续逐像素修补装饰作为默认收尾方式。语义优先副本应在正常流水线中依据已验证的对象覆盖和素材身份处理残余图层，保持私有收据、源归属与图标保护有效，重新运行静态和编辑验收；不扩大此前授权的源像素修改范围。

最后一处默认描边宽度修复后的真实样例正常入口 v11 语义策略回放，已同时通过运行期原生组件及语义门禁，原保真输入的语义失败仍保留。实际 PPTX 的 11 条完整原生关系结构核验及 LibreOffice 全页像素门槛通过；原门槛下 PDR 为 7.3940177854%、前景缺失为 3.5083712143%、MAD 为 9.5717570689。随后实际 PDF 路径检查发现局部五段连接器只显示三段，保留物理短臂与主路径断开，故不能称为实际显示拓扑通过。PowerPoint 实际编辑行为、统一全量工程验收及共享 Worker 部署仍未通过或未验证；详见[完整原生关系线网记录](image-to-editable-whole-native-network-20261027.md)。

## 本次行业资料复核后的执行决定

2026-10-27 再次直接读取上表 Microsoft、Miro、Lucidchart、yFiles 官方页面。Miro 明确将图片数字化结果交给用户检查及按需调整；Lucidchart 明确以 JPEG/PNG 重建可编辑形状；Microsoft 的重新路由方法以最短路径为目标，可能调整同一节点的连接点；yFiles 单独配置端点、路由样式、间距及保留既有路径的策略。这支持将结构与编辑作为默认目标，将路径装饰与逐像素还原独立评价，但没有证明行业允许错误关系或关键分支丢失。

本项目因此允许不承载含义的圆角、渐变和折点差异，也允许常规连接器重新走线。不会继续要求每个装饰角点都有完整源像素证明才算语义可用；原严格证据结果保留。关键回路、方向或分支一旦变化，仍属于结构问题；若仅凭当前截图无法确定某条物理短臂是否承载关系，不应自动删除或冒称装饰。

本轮独立四例对照进一步明确了应用兼容边界：当前 LibreOffice 无论直接读取绑定的原文件，还是读取静态去绑定副本，均将五段原生预设显示为三段。它不能作为这些路线的实际拓扑通过证明；仅用于诊断的普通形状对照保持了五段，但不满足交付完整原生连接器的要求，未采用为产品修复。正常渲染结果现单独返回原生路线及 Office 编辑尚未验证的诊断，详见[实际路径对照](../.codex-temp/connector-preset-import-20261027-v1/direct-path-comparison.json)。语义优先允许调整外观，不允许据此忽略关键回路或分支的显示变化。

“已有节点与确认关系一次生成完整原生连线”可作为支持范围内的产品目标。任意截图的关系识别、任意折点数量、复杂共享网络及跨应用编辑保持，不能因竞品宣传可编辑就宣称已解决。本轮没有进行竞品同图实测，也没有查到共同的 PDR、Missing 或 MAD 行业门槛。
