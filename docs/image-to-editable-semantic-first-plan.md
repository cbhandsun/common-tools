1. 默认 Worker 在 `team-native-rebuild.js` 中先调用 `boundedOcrSourceDeck`、再调用 native rebuild。`metadata.semanticFallback` 是外部 sidecar，声明式结果在重建之后追加；默认 Worker 未调用一个全局多模态结构规划器。

## 下一阶段的具体实现边界

1. **组件生成前输出 ScenePlan。** 包含区域树、对象候选类型、正文引用、节点/边候选、源 bbox/四边形、坐标变换、证据引用和 unresolved 状态。身份绑定源图哈希及识别器版本。
2. **语义指导复查，源图裁定几何。** 全局模型提出区域类型和关系假设；局部 OCR、线段/箭头与轮廓检测复核。文案、常识和阅读顺序不能补造边。只有冲突区域进入后续识别，实际花费继续扣现有总预算。
3. **分区路由。** 一页允许正文、流程、表格、图标混合。表格必须有行列证据；图标的小裁剪不能包含遗漏正文；父容器不自动拥有内部前景像素。
4. **编译为原生组件。** 文字为文本框；节点的容器、文字、图标形成逻辑组；关系编译为带对象引用的连接器；样式从原图测量。组件库负责实现语义，不能擅自改写或美化布局。
5. **失败有范围。** 类型或边仍不确定时，该区域保持 unresolved，不能继续花预算调其字体或宣称原生结构完整。已经验证的独立区域保留；最终发布仍需整页通过。
6. **验证顺序固定。** 类型/文本/父子关系/边方向与端点 → 源几何与层序 → 字体和外观 → 最终 PPTX 原生结构与真实编辑。每个阶段记录错误数，后阶段总分不能覆盖前阶段失败。

第一轮对照保持相同源图、现有总预算和最终门限，比较当前链路与结构规划链路。先检查区域遗漏、文字误作图形、图形误作文字、父区域错误、错误/缺失连接，再比较视觉指标。对标题、配色、比例、位置做适用扰动，确认不依赖样例内容。没有结构收益时，不扩充外观搜索。

结构理解正确之后，手写字形、弯曲边框和 JPEG 压缩下的字体拟合仍是独立问题。语义路线不能自动保证像素保真，也不能把文字轮廓路径当作可修改正文的文本框。
