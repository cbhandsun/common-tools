# 架构改进实施计划

本计划落实 2026-09-04 架构评估的六项建议。定位以 `ppt-roadmap.md` 为准：私有自用远程服务，优先稳定交付、低维护成本和可恢复性。状态必须以当前源码、实际命令结果或部署验收记录为依据；静态测试不能替代真实交付证据。

当前执行顺序及成本控制以 [合并交付批次](architecture-delivery-batches.md) 为准；下述 A–F 完整验收范围保持不变，历史逐批记录用于追溯。

## 工作边界

- 保留开始实施时工作区已有修改和用户工件；不批量暂存，不自动提交、发布或修改线上身份配置。
- 保持现有 CLI、MCP、Deck IR 和 PPTX 行为兼容；主入口只负责组装。
- 不提高架构预算、不关闭规则、不跳过测试；每批独立验证后再推进。
- 新输入边界覆盖正常、空、非法、极端、安全和失败路径。直接依赖显式声明。日志只记录有界的阶段、错误码和计数。
- 线上步骤先准备可审查的变更和合成验收材料，再按会话授权执行；缺失远程证据不能标记完成。

### 第六批：OCR 子进程故障恢复

- 回归先复现 SIGTERM 未导致关闭时永久等待、同步 spawn 异常直接传播原始消息的问题，再补终止升级：停止请求后等待一秒，未关闭则发送 SIGKILL，再等待一秒仍未关闭就以固定失败消息报告终止未确认。该结果不等于操作系统已回收进程。
- 保留第一个取消/超时/输出超限原因；信号异常不覆盖原始原因，后续关闭事件或有限截止时间给出最终结果。关闭后清除所有计时器，停止后释放并停止收集输出，慢速取消查询保持最多一次在途。
- 超时配置必须是 1–600,000 毫秒的整数，非法值在启动前拒绝；启动异常使用固定诊断，不携带原始进程消息。
