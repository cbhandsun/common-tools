---
name: image-to-editable
description: Create and inspect a local image-to-editable job using the common-tools CLI or MCP tools.
---

MCP task status `completed` means the asynchronous task stopped; it is not evidence of success. Check `isError`, the structured Job status, and `quality.passed`. A required quality-gate failure can retain a diagnostic PPTX for inspection, but it must be labeled as quality-failed rather than completed successfully.

Use this skill only for files inside the approved workspace. A Git Marketplace installation provides this Skill and its MCP declaration, but it does not by itself install the executable Runtime. Before creating a Job, run `common-tools doctor --capability image-to-editable --workspace <workspace>` and require `executable: true` and `imageToEditableEngine.available: true`. If the command is missing or the engine is unavailable, stop before creating a Job and tell the user to install or upgrade the complete matching Common Tools Runtime; never replace the official conversion with an ad-hoc Python/PPTX generator or claim an unverified fallback is complete. After preflight, run `common-tools plugin enable --capability image-to-editable`; it is idempotent and enables this independently installed plugin without removing other installed capabilities. A local source may be a valid PNG/JPEG no larger than 100 MiB, or one valid PDF/PPTX no larger than 60 MiB and 20 pages. A local image batch accepts 2–20 unique images from one directory in explicit order, with at most 60 MiB and 200,000,000 decoded pixels in total. PDF/PPTX input requires the approved `normalize-cli.js` adapter (PPTX may instead use `normalize-powerpoint-com.js`) and `normalize.maxPages` from 1 through 20. This local capability requires an explicit workspace-contained slideclone config that declares its OCR, vision, rendering and quality providers; its `inputDir` must be the input file directory and its `outputDir` must equal the requested output directory. It does not silently choose a provider. Prefer the `create_editable_job` MCP tool when it is available: pass exactly one of `input: <file>` or `inputs: [<ordered image paths>]`; never pass both. Otherwise run `common-tools editable run --input <file> --out <directory> --config <slideclone.config.json>` for one source, or `common-tools editable batch --inputs <ordered,comma-separated,image-paths> --out <directory> --config <slideclone.config.json>` for multiple images, then inspect the returned terminal Job. Do not request access to paths outside the workspace and do not claim conversion has completed until the Job has a terminal result and quality report.

For the optional remote team OCR profile, create the exact Worker input with `common-tools team editable-source-archive --workspace <workspace> --input <png|jpg|pdf|pptx> --out <archive.tar.gz>` or use `--inputs <ordered,comma-separated,image-paths>` for up to 20 images. Pass its returned `application/gzip` content type and content length to `create_team_upload_target`, upload that archive to the returned scoped URL, then call `create_team_job` with the returned object key and a fresh idempotency key. Never upload source files directly, choose a normalizer/OCR executable/model/language through MCP arguments, or reuse an upload target for another capability. An image batch must pass `raw-image-batch-validated`; a PDF/PPTX must pass `document-pages-normalized`. Raw-source team output must pass `local-production-profile-aligned` on every page and uses the same production reconstruction profile as the local high-fidelity path. It preserves refined local icon crops when native approximation would lose detail while objectifying text, containers, connectors, tables, and banners. Its full-slide fidelity residual erases both native objects and retained local crops before overlay, so moving them does not reveal raster duplicates; require `residual-native-duplicates-removed` whenever a residual is present. The residual intentionally retains complex details that cannot yet be rebuilt reliably; do not describe every visual as native. The team Worker renders every generated page, compares it with the normalized source, and enforces `pixel-diff-ratio <= 0.08`; describe the result as visually verified only when `local-production-profile-aligned`, `residual-native-duplicates-removed` (when present), `quality-rendered`, and `visual-fidelity` pass. A failed or missing gate remains structurally editable but visually unverified.

When the approved source has already been understood as native components, preserve that work using the existing structured Deck IR path instead of rasterizing it and repeating OCR. With a matching Local Runtime and Worker that support structured source verification, use `common-tools team editable-source-archive --input <deck.json> --out <archive.tar.gz>`. The deck must contain `page.source.pageImage` for every page, pointing to its approved full-page PNG/JPEG under `assets/`; cropped icons remain separate `images[].assetPath` entries. Reuse the existing local component/connector builders and icon-crop refinement to prepare the IR; do not invent component relationships from OCR order. The command validates the deck, copies only referenced assets, and preserves editable objects. Require `deck-ir-validated`, `quality-rendered`, `visual-fidelity`, and `complex-graphic-native-gate` on the returned Job. A legacy Worker that accepts Deck IR without reporting those checks has not verified this path. This route reuses supplied component understanding; it does not imply automatic understanding of arbitrary source pages.
